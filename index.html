Gate evidence milestone

231 Gates. Evidence before execution.

QEC separately tracks symbolic directional Gate rules. Every direction remains fail-closed until replayable evidence supplies the program, deterministic seed, exact Gate index, and observed machine topology needed to approve it. Symbolism alone never activates a Gate.

This is not the same layer as the 22-letter OpenQASM mapping. It is shown here because the same design principle governs both: stronger claims require stronger, replayable evidence.

A few useful distinctions

Before you explore further.

Do I need Hebrew or programming experience?

You can start in the Tree console with the existing אור example. Each step shows its letter, route, and state change. The IvritCode workbench adds a Hebrew keyboard and guided lessons when you want to write a program.

What is the relationship between QEC, IvritCode, and IvritOS?

Quantum Etz Chaim describes the architecture. IvritCode is the language and learning laboratory. IvritOS is the proposed operating-system layer. The working pages expose specific implementations and identify experimental or reserved features.

Is this a physical quantum computer?

The current Tree runtime is deterministic software, and QEC-1 is a classical control-and-display interface. The separate OpenQASM projection exports circuit source for external tools. Parser and simulator evidence is limited to the published test corpus; it does not establish quantum hardware execution or speedup.

What do the Tree and Hebrew correspondences mean here?

The Tree of Life provides symbolic inspiration. Letter operations, service roles, and path assignments are project-defined engineering conventions. They are not statements of religious authority or established physical laws.

How can I check a result?

Complete a run in the Tree console and download its Run Passport. Open that file in Run evidence to inspect its contract, trace, and available validation records. The physical bench workflow records hardware acknowledgements separately.
